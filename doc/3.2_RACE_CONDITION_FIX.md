# 🐛 Race Condition Fix: Inkonsistente Kometen-Positionen

**Problem:** Worker berechnen unterschiedliche Zeiten → Überschreiben sich im gleichen Bucket  
**Datum:** 2024-10-31  
**Status:** FIXED

---

## Root Cause

### Szenario

```
User Request 1: time=2024-10-31T20:15:00Z
  ↓
API triggert Worker mit: time_bucket="2024-10-31T20:15:00Z"
  ↓
Worker berechnet Positionen FÜR 20:15 Uhr
  ↓
Worker speichert in Bucket: "20241031T20"

User Request 2: time=2024-10-31T20:45:00Z
  ↓
API triggert Worker mit: time_bucket="2024-10-31T20:45:00Z"
  ↓
Worker berechnet Positionen FÜR 20:45 Uhr
  ↓
Worker ÜBERSCHREIBT Bucket: "20241031T20"  ← BUG!
```

### Problem

**Worker berechnen für unterschiedliche Zeiten, speichern aber im GLEICHEN Bucket!**

```python
# workers/comet_worker.py:113 (ALT - FALSCH!)
time_bucket_dt = datetime.fromisoformat(time_bucket_str.replace('Z', '+00:00'))
# → 2024-10-31 20:15:00+00:00

# comets.py:432
time_bucket = time_bucket_utc(dt_utc, COMET_CACHE_BUCKET_HOURS)
# → "20241031T20"
```

**Effekt:**
- Worker 1 berechnet für 20:15 → Komet bei 20.5° Alt
- Worker 2 berechnet für 20:45 → Komet bei 22.3° Alt (überschreibt!)
- Worker 3 berechnet für 20:10 → Komet bei 19.8° Alt (überschreibt!)

**User bekommt zufällige Daten je nachdem welcher Worker zuletzt geschrieben hat!**

---

## Fix

### Worker sollen NUR Bucket-Boundaries berechnen

```python
# workers/comet_worker.py:113 (NEU - KORREKT!)
time_bucket_dt = datetime.fromisoformat(time_bucket_str.replace('Z', '+00:00'))
# Runde auf Stunden-Boundary (z.B. 20:15 → 20:00)
time_bucket_dt = time_bucket_dt.replace(minute=0, second=0, microsecond=0)
# → 2024-10-31 20:00:00+00:00
```

**Jetzt:**
- Worker 1 berechnet für 20:00 → Komet bei 20.0° Alt
- Worker 2 berechnet für 20:00 → Komet bei 20.0° Alt (identisch!)
- Worker 3 berechnet für 20:00 → Komet bei 20.0° Alt (identisch!)

**Alle Worker berechnen für die GLEICHE Zeit → Konsistente Daten!**

## Warum das auch Asteroiden betraf (weniger sichtbar)

**Asteroiden bewegen sich langsamer:**
- 20:15 → Position A (z.B. 45.123°)
- 20:45 → Position A+ε (z.B. 45.125°)
- Differenz: 0.002° (kaum sichtbar!)

**Kometen bewegen sich schneller:**
- 20:15 → Position A (z.B. 20.5°)
- 20:45 → Position A+Δ (z.B. 22.3°)
- Differenz: 1.8° (deutlich sichtbar!)

**Deshalb waren die Sprünge bei Kometen viel auffälliger!**

## Lessons Learned

### 1. Worker sollten immer für Bucket-Boundaries berechnen
```python
# IMMER Runden:
time_bucket_dt = time_bucket_dt.replace(minute=0, second=0, microsecond=0)
```

### 2. ON CONFLICT in PostgreSQL verwenden
```sql
INSERT INTO cached_positions (...)
VALUES (...)
ON CONFLICT (object_type, location_key, time_bucket)
DO NOTHING  -- ← Überschreibe NICHT!
```

### 3. Logging hinzufügen
```python
logger.info(f"Computing for bucket time: {time_bucket_dt.isoformat()}")
logger.info(f"Original request time: {time_bucket_str}")
logger.info(f"Rounded to bucket: {time_bucket_dt.isoformat()}")
```
