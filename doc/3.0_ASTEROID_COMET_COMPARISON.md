# Asteroiden vs. Kometen - Vollständiger Architektur-Vergleich

**Datum:** 2024-10-31  
**Zweck:** Vergleich der Berechnungs-Pipeline, Worker-Nutzung und Analyse der Kometen-Positionssprünge

---

## Executive Summary

**Hauptunterschied:** Beide Systeme sind strukturell **identisch**, aber ein **kritischer Bug** in der Cache-Interpolation verursacht die Kometen-Sprünge:

- ✅ **Asteroiden:** Funktionieren perfekt
- ❌ **Kometen:** Unvorhersehbare Azimut-Sprünge bei Zeitnavigation
- 🐛 **Root Cause:** `cache_interpolation.py` verwendet **DISABLED INTERPOLATION** - wählt nur den nächsten Bucket ohne Interpolation
- 📊 **Bucket Size:** Beide verwenden 1-Stunden-Buckets
- 🔄 **Interpolation:** Aktuell **deaktiviert** (Zeile 50-77 in `cache_interpolation.py`)

#### Schritt 2: Cache Loader

```python
def load_asteroids_with_interpolation(lat, lon, elevation, dt_utc, ...):
    # Berechne umgebende Buckets
    bucket1_dt, bucket2_dt, factor = get_interpolation_buckets(dt_utc, 1)
    
    # Lade beide Buckets
    list1 = _load_asteroid_bucket(lat, lon, elevation, bucket1_dt, ...)
    list2 = _load_asteroid_bucket(lat, lon, elevation, bucket2_dt, ...)
    
    # ⚠️ INTERPOLATION DISABLED (Zeile 52-59)
    if list1 and list2:
        if factor < 0.5:
            return list1  # Verwende bucket1
        else:
            return list2  # Verwende bucket2
    
    # Fallback
    if list1:
        return list1
    if list2 and (bucket2_dt - dt_utc).total_seconds() / 3600 <= 1.0:
        return list2
    
    return None  # Cache MISS
```

```python
def load_bright_asteroids(..., current_dt):

    df_pickle = get_asteroid_dataframe()
    df = pickle.loads(df_pickle)
    
    # Filtere nach absoluter Helligkeit
    candidates = df[df['magnitude_H'] <= 12.0]
    
    # Für jeden Asteroiden
    for index, row in candidates.iterrows():
        # Erstelle Orbit
        orbit = mpc.mpcorb_orbit(row, ts, ...)
        target = sun + orbit

        t = ts.from_datetime(current_dt)
        astrometric = observer.at(t).observe(target)
        
        # Altitude/Azimuth
        alt, az, _ = astrometric.apparent().altaz()
        
        # Apparent Magnitude (IAU H-G System)
        r = astrometric.distance().au
        delta = astrometric.radec()[2].au
        phase_angle = acos((r²+Δ²-1)/(2rΔ))
        apparent_mag = asteroid_apparent_magnitude(H, G, r, delta, phase_angle)
        
        # Filtere nach apparent magnitude
        if apparent_mag > max_magnitude:
            continue
        
        # Rise/Set/Transit (erste 50 Objekte)
        if events_computed < 50:
            rise_time, set_time, transit_time = compute_events(...)
        
        asteroid_list.append({
            'name': designation,
            'altitude': alt.degrees,
            'azimuth': az.degrees,
            'magnitude': round(apparent_mag, 1),
            'distance': round(delta, 3),
            'type': 'asteroid',
            'symbol': '⚸',
            ...
        })
    
    # Speichere in PostgreSQL Cache
    store_asteroid_positions(
        representative_id=0,
        loc_key=location_key(lat, lon, elevation),
        time_bucket=time_bucket_utc(current_dt, 1),
```

### 3.2 Task Distribution

**Routing Keys:**
- `compute.asteroid` → `asteroid.compute` Queue
- `compute.comet` → `comet.compute` Queue

**Worker Binding:**
```python
# workers/asteroid_worker.py:62-84
channel.queue_declare(
    queue='asteroid.compute',
    durable=True,
    arguments={
        'x-queue-type': 'quorum',  # Replicated across RabbitMQ cluster
        'x-message-ttl': 3600000   # 1 Stunde
    }
)

channel.queue_bind(
    exchange='computation.direct',
    queue='asteroid.compute',
    routing_key='compute.asteroid'
)

# QoS: Nur 1 Task gleichzeitig pro Worker
channel.basic_qos(prefetch_count=1)
```

### 3.3 Worker Lifecycle

```python
# workers/asteroid_worker.py:216-230
def start(self):
    channel.basic_consume(
        queue='asteroid.compute',
        on_message_callback=self.callback,
        auto_ack=False  # Manuelle ACKs
    )
    
    channel.start_consuming()

def callback(self, ch, method, properties, body):
    task = json.loads(body)
    
    # Berechnung durchführen
    results = self.compute_asteroids(...)
    
    # ACK nach erfolgreicher Berechnung
    ch.basic_ack(delivery_tag=method.delivery_tag)
```

### 3.4 Load Balancing

**Fair Dispatch durch RabbitMQ:**
- prefetch_count=1 → Worker holt nur 1 Task
- Nächster Task erst nach ACK
- Automatische Lastverteilung
- Retry bei Fehler (requeue=True)

**Beispiel mit 4 Workern:**
```
Task 1 → Worker 1 (busy)
Task 2 → Worker 2 (busy)
Task 3 → Worker 3 (busy)
Task 4 → Worker 4 (busy)
Task 5 → (waiting)
Worker 1 ACK → Task 5 → Worker 1
```

```python
# cache_utils.py:41-49
def time_bucket_utc(dt, bucket_hours=1):
    bucket_hour = (dt.hour // bucket_hours) * bucket_hours
    return f"{dt:%Y%m%d}T{bucket_hour:02d}"

# Beispiele:
# 2024-10-31 14:23:45 → "20241031T14"
# 2024-10-31 14:59:59 → "20241031T14"
# 2024-10-31 15:00:00 → "20241031T15"
```

### 4.2 PostgreSQL Schema

```sql
-- cached_positions Tabelle
CREATE TABLE cached_positions (
    id SERIAL PRIMARY KEY,
    object_type VARCHAR(20) NOT NULL,  -- 'asteroid' oder 'comet'

    time_bucket VARCHAR(20) NOT NULL,

CREATE INDEX idx_cached_positions_lookup 
ON cached_positions(object_type, location_key, time_bucket);
```

### 4.3 Cache Lookup

```python
# db_utils.py
def get_asteroid_positions(loc_key, time_bucket, max_age_seconds):
    with get_db_connection() as conn:
        cursor = conn.cursor()
        cursor.execute("""
            SELECT positions_json, 
                   EXTRACT(EPOCH FROM (NOW() - computed_at)) as age_seconds
            FROM cached_positions
            WHERE object_type = 'asteroid'
              AND location_key = %s
              AND time_bucket = %s
              AND EXTRACT(EPOCH FROM (NOW() - computed_at)) < %s
            ORDER BY computed_at DESC
            LIMIT 1
        """, (loc_key, time_bucket, max_age_seconds))
        
        row = cursor.fetchone()
        if row:
            return row[0]  # JSONB Array
        return None
```

## 5. 🐛 ROOT CAUSE: Kometen-Sprünge

### 5.1 Problem-Identifikation

**Symptom:**
- Asteroiden: Smooth, kontinuierliche Bewegung bei +1h/-1h Navigation
- Kometen: Unvorhersehbare Sprünge in Azimut/Position

**Analyse:**

```python
# api/cache_interpolation.py:50-77 (KRITISCH!)

# DISABLED INTERPOLATION - Using exact buckets only
if list1 and list2:
    # Choose the bucket closer to the requested time
    if factor < 0.5:
        logger.info(f"Using bucket1 (closer): {bucket1_dt.isoformat()}")
        return list1  # ← Bucket 14:00
    else:
        logger.info(f"Using bucket2 (closer): {bucket2_dt.isoformat()}")
        return list2  # ← Bucket 15:00
```

**Szenario:**
```
Zeit     14:29  14:30  14:31  ...  14:59  15:00  15:01
         ────────┬──────────────────┬──────────────────
Bucket1  14:00   │      14:00      │     14:00
Bucket2  15:00   │      15:00      │     15:00
factor   0.48    │      0.50       │     0.52
         ────────┴──────────────────┴──────────────────
Returned list1   │      list2!     │     list2
         ────────┴──────────────────┴──────────────────
                 ▲
                 SPRUNG HIER! (30 Min Zeitdifferenz)
```

### 5.2 Warum Asteroiden besser erscheinen

**Hypothese:** Asteroiden bewegen sich langsamer als Kometen!

```python
# Asteroiden: Typische Bewegung
# Period: 3-6 Jahre
# Angular velocity: ~0.01°/Stunde

# Kometen: Schnellere Bewegung
# Period: 5-200 Jahre (oder parabolisch)
# Angular velocity: ~0.1-1.0°/Stunde (näher am Perihel!)
```

**Effekt:**
- Asteroiden: Sprung von 14:00→15:00 = ~0.01° kaum sichtbar
- Kometen: Sprung von 14:00→15:00 = ~0.5° deutlich sichtbar!

### 5.3 Lösung

**Option 1: Interpolation aktivieren**
```python
# api/cache_interpolation.py:50-77
if list1 and list2:
    # LINEAR INTERPOLATION statt Bucket-Switch
    return interpolate_object_list(list1, list2, factor)
```

**Option 2: Kleinere Buckets**
```python
# Reduziere auf 15-Minuten-Buckets
COMET_CACHE_BUCKET_HOURS = 0.25  # 15 Minuten
```

**Option 3: Hybrid**
```python
# Interpolation für Kometen, Bucket für Asteroiden
if kind == 'comets':
    return interpolate_object_list(list1, list2, factor)
else:
    return list1 if factor < 0.5 else list2
```

**Problem:**

**Effekt:**
- Bei factor=0.49 → Bucket 14:00 (14:00 Position)
- Bei factor=0.51 → Bucket 15:00 (15:00 Position)
- **Sprung:** 1 Stunde Zeitdifferenz in Position!

**Warum Kometen stärker betroffen:**
- Kometen bewegen sich schneller als Asteroiden
- 1h Sprung bei Kometen = ~0.5° Azimut-Differenz (sichtbar!)

### 11.2 Cache Hit Rate

```bash
# PostgreSQL Query
SELECT 
    object_type,
    COUNT(*) as total_queries,
    SUM(CASE WHEN age_seconds < 3600 THEN 1 ELSE 0 END) as cache_hits,
    ROUND(100.0 * SUM(CASE WHEN age_seconds < 3600 THEN 1 ELSE 0 END) / COUNT(*), 2) as hit_rate
FROM cached_positions
WHERE computed_at > NOW() - INTERVAL '7 days'
```
