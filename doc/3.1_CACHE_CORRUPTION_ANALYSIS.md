# 🐛 Cache Corruption Analysis: Inkonsistente Kometen-Sprünge

**Problem:** Kometen springen wild inkonsistent: 20°→50°→11° Altitude  
**Datum:** 2024-10-31  
**Severity:** CRITICAL - Cache liefert falsche Objekte zurück

---

## Problem-Beschreibung

### Symptom

Bei Navigation durch Zeit (z.B. +1h, +1h, +1h):
```
20:00 Uhr → Komet C/2023 A3 bei 20° Altitude
21:00 Uhr → Komet C/2023 A3 bei 50° Altitude  ← Unmöglich! (+30° in 1h)
22:00 Uhr → Komet C/2023 A3 bei 11° Altitude  ← Unmöglich! (-39° in 1h)
```

**Das ist NICHT Interpolation-Problem**, sondern:
- Cache gibt für denselben Komet-Namen verschiedene Objekte zurück
- Oder Cache matcht Zeit-Buckets falsch
- Oder mehrere Kometen haben denselben Namen

---

## Root Cause Analysis

### 1. Cache-Lookup Mechanismus

```python
# db_utils.py:203-216 (KRITISCH!)
def get_comet_positions(location_key: str, time_bucket: str, max_age_seconds: int):
    cursor.execute("""
        SELECT position_data FROM cached_positions
        WHERE object_type = 'comet'
          AND location_key = %s
          AND time_bucket = %s
        ORDER BY computed_at DESC LIMIT 1
    """, (location_key, time_bucket))
    
    row = cursor.fetchone()
    if row and row['position_data']:
        return pickle.loads(bytes(row['position_data']))
    return None
```

**Problem:** 
- KEIN TTL-Check! (max_age_seconds wird ignoriert!)
- Nur `ORDER BY computed_at DESC LIMIT 1` - nimmt neueste Berechnung
- Wenn Zeit-Bucket falsch ist → falscher Cache!

### 2. Time Bucket Berechnung

```python
# cache_utils.py:41-49
def time_bucket_utc(dt, bucket_hours=1):
    bucket_hour = (dt.hour // bucket_hours) * bucket_hours
    return f"{dt:%Y%m%d}T{bucket_hour:02d}"

# Beispiel:
# 20:00 → "20241031T20"
# 20:30 → "20241031T20"  ← Gleicher Bucket
# 20:59 → "20241031T20"  ← Gleicher Bucket
# 21:00 → "20241031T21"  ← Neuer Bucket
```

**Korrekt!** Zeit-Buckets sind konsistent.

### 3. Cache-Interpolation Logic

```python
# api/cache_interpolation.py:108-125
def load_comets_with_interpolation(lat, lon, elevation, dt_utc, ...):
    bucket1_dt, bucket2_dt, factor = get_interpolation_buckets(dt_utc, 1)
    
    list1 = _load_comet_bucket(..., bucket1_dt, ...)
    list2 = _load_comet_bucket(..., bucket2_dt, ...)
    
    # DISABLED INTERPOLATION
    if list1 and list2:
        if factor < 0.5:
            return list1  # ← Bucket 20:00
        else:
            return list2  # ← Bucket 21:00
```

**Problem identifiziert!**

Bei `factor=0.50` (genau 20:30) wechselt die Funktion von list1 → list2!

```
Zeit    20:29  20:30  20:31  ...
factor  0.48   0.50   0.52
Return  list1  list2  list2  ← SPRUNG HIER!
```

Aber das erklärt **NICHT** die inkonsistenten Werte (20°→50°→11°)!

## 🔧 Fix-Strategie

### Option 1: Verwende `designation` statt `name` als Key

**Problem:** Frontend verwendet `name` als Display  
**Lösung:** Verwende `designation` als eindeutigen Key

```python
# api/routes/comets.py:220

# NEU:

```

### Option 2: Kombiniere Name + Designation

```python
# comets.py:712-726

    'id': unique_id,           # ← NEU: Eindeutiger Key
    'name': name,              # ← Display Name
    'designation': designation,
    ...

```

### Option 3: Cache-Lookup mit TTL

```python
# db_utils.py:203-216 (FIX!)
def get_comet_positions(location_key: str, time_bucket: str, max_age_seconds: int):
    cursor.execute("""
        SELECT position_data,
               EXTRACT(EPOCH FROM (NOW() - computed_at)) as age_seconds
        FROM cached_positions
        WHERE object_type = 'comet'
          AND location_key = %s
          AND time_bucket = %s
          AND EXTRACT(EPOCH FROM (NOW() - computed_at)) < %s  ← NEU!
        ORDER BY computed_at DESC LIMIT 1
    """, (location_key, time_bucket, max_age_seconds))
```

## Zusammenfassung

### Root Cause

1. **Cache-Lookup ignoriert TTL** (max_age_seconds wird nicht verwendet)
2. **Komet-Namen sind nicht eindeutig** (mehrere Kometen können denselben Namen haben)
3. **Frontend verwendet Name statt Designation** als Key

### Sofort-Fixes

1. ✅ TTL-Check in `get_comet_positions()` aktivieren
2. ✅ Verwende `designation` als eindeutigen Key
3. ✅ Debug-Logging für Cache-Hits hinzufügen

### Langfristig

1. Cache-Schema erweitern: `UNIQUE(object_type, object_id, location_key, time_bucket)`
2. Komet-ID aus MPC-DataFrame verwenden statt Name
3. Frontend: Zeige Name, verwende aber designation für Tracking
